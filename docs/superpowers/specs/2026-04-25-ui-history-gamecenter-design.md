# 三衍 HUD / 历史记录 / Game Center 设计

**项目**：ai-game-three（TriYan）  
**日期**：2026-04-25  
**状态**：已确认，待实现

## 1. 目标

在不改变当前棋盘位置、尺寸和核心玩法的前提下，完成以下四项改进：

- 顶部增加“下一个数字”提醒，仅展示一个即将生成的数字
- 替换现有字体方案，让标题和 HUD 更有游戏感，同时保留棋盘数字可读性
- 重做 Game Over 界面，修复当前布局混乱问题
- 增加历史记录能力，并接入 Apple Game Center 保存最高分

## 2. 非目标

- 不重做棋盘玩法、生成规则、移动规则、分数规则
- 不移动棋盘，不缩小棋盘给 HUD 让位
- 不把逐局历史明细存入 Game Center
- 不新增独立首页或完整菜单系统

## 3. 布局设计

### 3.1 顶部 HUD

HUD 固定在安全区顶部，完全脱离棋盘区域。

- 左侧：标题“三衍”
- 中间：`下一个：X`
- 右侧：实时分数
- 右侧或标题邻近位置：历史记录入口按钮

约束：

- 棋盘位置和尺寸保持当前真机版本不变
- HUD 必须始终位于安全区内，不能与棋盘重叠
- 旋转或视图尺寸变化时，HUD 与棋盘独立重排

### 3.2 下一个数字提醒

- 只显示一个预告值
- 采用文本形式：`下一个：2`
- 预告值直接读取 `Spawner.previewTile`
- 每次新 tile 生成后立即刷新

## 4. 字体与视觉设计

### 4.1 字体策略

采用两类字体职责分离：

- 标题、HUD 标题、弹层标题：更圆润、游戏感更强
- 棋盘数字、分数、按钮、列表正文：优先清晰易读

实现策略：

- 优先使用系统可用的圆润字体风格或等价粗体组合
- 不引入外部字体资源，避免真机兼容和打包复杂度
- 如果目标字体在设备上不可用，回退到系统粗体

### 4.2 视觉约束

- 维持当前浅色背景与 tile 色板
- 不让 HUD 视觉权重超过棋盘
- 分数和预告的字号略小于标题

## 5. Game Over 设计

Game Over 改为屏幕中心卡片式弹层。

结构：

- 全屏半透明遮罩
- 中心卡片
- 标题：`游戏结束`
- 信息行：
  - 本局分数
  - 历史最高
- 操作按钮：
  - `再来一局`
  - `历史记录`

约束：

- 卡片相对屏幕中心定位，不依赖棋盘局部坐标
- 尺寸变化时保持居中和间距稳定
- 弹层内容不允许互相重叠

## 6. 历史记录设计

### 6.1 数据范围

逐局历史保存在本地，记录以下字段：

- 时间
- 分数
- 最高数字

额外派生信息：

- 历史最高分
- 最近若干局记录

### 6.2 展示方式

历史记录通过弹层展示，先不单独建页面。

入口：

- 顶部 HUD 历史按钮
- Game Over 卡片内“历史记录”按钮

内容：

- 顶部标题
- 历史最高
- 最近若干局列表
- 每项显示时间、分数、最高数字
- 关闭按钮

### 6.3 本地存储策略

复用并扩展现有 `StatsStore`。

- 保留已有累计统计能力
- 新增逐局记录数组的读写
- 逐局记录上限固定，避免无限增长
- 记录格式采用 `Codable` + `UserDefaults` 数据

## 7. Game Center 设计

### 7.1 职责边界

Game Center 只负责最高分排行榜，不负责逐局历史列表。

- 本地历史是主数据
- Game Center 是最高分同步通道

### 7.2 行为

- App 启动时尝试认证本机玩家
- 一局结束后：
  - 保存本地历史
  - 若本局分数超过已知最高分，则提交到 Game Center
- Game Center 不可用时，游戏照常运行

### 7.3 代码结构

新增轻量 `GameCenterService`：

- 认证玩家
- 查询/缓存本地已知最高分
- 提交新的最高分

`GameScene` 不直接写 GameKit 细节，只调用服务接口。

  - Game Center 认证和最高分提交封装

## 9. 实现顺序

1. 扩展 `DesignSystem`，统一 HUD / 弹层 / 字体常量
2. 扩展 `StatsStore`，补逐局历史模型和读写
3. 新增 `GameCenterService`
4. 重构 `GameScene` 顶部 HUD，增加“下一个数字”和历史入口
5. 重做 Game Over 卡片与历史弹层
6. 在对局结束时接入本地保存与 Game Center 提交
7. 真机构建并安装到 `duo2.4` 验证

## 10. 风险与约束

- Game Center 需要真机和有效账号环境，模拟器验证价值有限
- 系统字体可选项有限，最终效果可能需要在真机上微调字号和字重
- 现有 `GameScene` 同时负责渲染和交互，新增弹层时需要控制节点层级，避免互相遮挡

## 11. 自检结论

- 无占位符
- HUD、Game Over、历史和 Game Center 的职责边界明确
- 范围收敛在单轮实现内，没有扩散成菜单系统重做
- Game Center 与逐局历史的边界已明确，避免错误地把明细塞入排行榜系统
